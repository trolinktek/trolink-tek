# OEM/ODM Pilot Build Exit Criteria for Connected-Car Accessories

A pilot build should exit to production only when buyer and supplier agree what configuration was built, which planned evidence is complete, which exceptions remain and who owns the next decision. A demonstration unit is not automatically a production release. For a CarPlay adapter, AI Box or Smart Car Screen, link the approved BOM and firmware to functional evidence, packaging, traceability, known deviations and post-pilot actions. The purpose is not to invent a universal pass rate. It is to stop an unbounded sample result becoming a mass-production promise.

## Define the release unit

Before the build begins, name the release unit: product SKU, hardware revision, firmware, supplied accessories, packaging version and target market or channel. If a cable, mount, language insert or label changes, the buyer should know whether the pilot evidence still applies. This identity turns a pilot from a collection of devices into a controlled project output. Record actual configuration and reference documents; mark a pending part or firmware as an open deviation rather than allowing it to disappear in a verbal handover.

## Use an exit table that leads to a decision

| Exit area | Decision question | Evidence to retain |
| --- | --- | --- |
| Configuration | Is SKU, BOM, firmware and accessory set identifiable? | Revision list and controlled sample IDs |
| Function | Were agreed use cases checked on the defined setup? | Test record and exceptions |
| Process | Can the factory repeat defined assembly and checks? | Process flow and open actions |
| Packaging | Does the approved kit match the commercial offer? | Artwork, pack-out and sample review |
| Traceability | Can a case be tied to build and configuration? | Lot or serial mapping route |
| Deviations | Are open issues bounded and owned? | Deviation log, risk and due date |

The table does not require every project to test the same features. It requires the buyer to state which features matter and how a decision will be made. For vehicle-dependent product, use a defined host and cable route rather than a generic claim that the pilot worked in cars.

## Treat deviations as business decisions

Imagine a private-label Smart Car Screen pilot that performs agreed display and phone-projection checks, but the final regional insert is still under translation review. The units may be technically usable, yet packaging release is open. The buyer can hold shipment, approve limited sample use with controlled communication, or authorize a revised pack after review. None of those choices should be hidden behind a passed functional test.

Likewise, an unresolved firmware observation must have a named scope. Is it a blocker for the promised use case? Does it affect every unit, a target vehicle group or only a non-launch feature? What temporary wording, if any, is authorized? Record and retest after the revision. The [repeat-order change-control guide](/blog/private-label-carplay-adapter-repeat-order-change-control/) is useful once first release moves into later lots.

## Pilot-exit workflow

1. Freeze pilot configuration and identify samples.
2. Review agreed test and packaging evidence against that configuration.
3. Log every deviation with scope, owner, decision due date and customer-facing impact.
4. Decide: release, conditional limited use, rework/retest, or hold.
5. Link the decision to next build, production records and support information.

## FAQ

### Can a pilot build be released with open items?

Only through a controlled decision with scope and ownership. Do not treat an open item as closed because a pilot sample powers on.

### Does a pilot prove mass-production quality?

No. It supplies project evidence for a defined configuration. Production release also needs an agreed process, traceability and ongoing control plan.

### What should the buyer ask for before approving the next build?

Ask for the controlled configuration, evidence summary, deviation log, packaging state, traceability route and supplier’s proposed decision.
